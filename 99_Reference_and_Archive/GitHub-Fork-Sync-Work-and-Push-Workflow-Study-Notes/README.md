# GitHub Fork, Sync, Work & Push Workflow

A practical step-by-step guide to understanding the complete GitHub contribution workflow—from **forking a repository** to **syncing changes**, **working locally**, and **pushing updates** back to your GitHub repository.

## 📖 Overview

This study guide demonstrates the real-world GitHub workflow used by developers when contributing to repositories they do not own. It covers:

- Forking a repository
- Cloning your fork (SSH/HTTPS)
- Working in a local repository
- Creating files and folders
- Syncing your fork when the original repository changes
- Updating your local repository
- Committing your work
- Using `git pull --rebase`
- Pushing your changes to GitHub
- Git best practices for beginners

## 🎯 Learning Objectives

After completing this guide, you will be able to:

- Understand the difference between the original repository and your fork.
- Clone your own GitHub repository.
- Work safely in your local repository.
- Keep your fork synchronized with the original repository.
- Update your local repository before pushing changes.
- Push your work confidently without losing updates.
- Follow a clean Git workflow used in real-world projects.

## 📂 Repository Workflow

```text
Original Repository
        │
        ▼
      Fork
        │
        ▼
   Your GitHub Fork
        │
        ▼
      Clone
        │
        ▼
   Local Repository
        │
        ▼
 Create / Edit Files
        │
        ▼
 git status
        │
        ▼
 git add .
        │
        ▼
 git commit
        │
        ▼
Owner updates repository
        │
        ▼
Sync Fork (GitHub)
        │
        ▼
git pull --rebase origin main
        │
        ▼
git push origin main
```
